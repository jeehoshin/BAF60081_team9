1분 이해: 깃허브 협업의 황금 룰!

깃허브는 쉽게 말해 "모두가 공유하는 구글 드라이브 원본 문서(main)"입니다.

🚨 절대 하지 말아야 할 것: 원본 문서(main)에 모두가 동시에 글을 쓰면 문장이 꼬이고 난리가 납니다.

그래서 우리는 아래 3단계 규칙만 지킵니다:

🌿 1. 내 브랜치 만들기 ➜ 원본(main)을 복사해서 나만의 연습장(branch)을 만든다.
💻 2. 내 방에서 실컷 수정 ➜ 내 연습장에서 마음껏 코드를 고치고 테스트한다. (남에게 피해 없음!)
📬 3. PR(검토 요청) 올리기 ➜ "저 다 고쳤어요! 원본에 합쳐주세요(Merge)" 하고 팀원에게 승인받는다.
0

[팀장용] 팀원들 초대하기 (Collaborator)

팀원들이 우리 저장소에 들어와서 코드를 올리려면 초대장을 먼저 보내야 합니다.

  1. GitHub 저장소(BAF60081_team9) 접속
  2. 상단 메뉴에서 Settings 클릭
  3. 왼쪽 세로 메뉴에서 Collaborators 클릭
  4. 초록색 Add people 버튼 클릭 후 팀원의 GitHub 아이디(또는 이메일) 검색하여 초대!
💌 팀원 확인 사항: 팀원은 본인 이메일이나 GitHub 알림창으로 온 초대장을 열어 [Accept invitation]을 반드시 눌러야 합니다.
1

[팀원용] 처음 1회: 내 컴퓨터로 프로젝트 복사해오기 (Clone)

터미널(또는 명령 프롬프트)을 열고, 프로젝트를 저장하고 싶은 폴더로 이동한 뒤 딱 한 번 실행합니다:

저장소 통째로 다운로드받기:
git clone https://github.com/jeehoshin/BAF60081_team9.git
cd BAF60081_team9
✅ 이제 내 컴퓨터에도 전체 백엔드, 프론트엔드 최신 코드가 복사되었습니다!
2

작업 시작: 나만의 작업 공간(브랜치) 만들기

코드를 한 글자라도 고치기 전에, 반드시 나만의 브랜치로 방을 옮겨야 합니다.

최신 main에서 새 브랜치 만들고 이동하기:
# 문법: git switch -c 브랜치이름 (내이름/기능명 추천)
git switch -c feature/api-collector    # 예: 외부 API 담당자
# 또는
git switch -c feature/design-fix       # 예: 디자인 수정

💡 git branch 명령어를 쳤을 때 내가 만든 브랜치 이름 앞에 별표(*)가 붙어 있으면 성공입니다.

3

코드 수정 후 저장하기 (Commit)

VS Code 등에서 코드를 자유롭게 수정하고 저장하세요. 수정이 끝났으면 Git에 "여기까지 기록해 줘!" 하고 도장을 찍습니다.

수정한 파일 장바구니에 담기:
git add .
기록 설명(커밋 메시지) 적고 도장 쾅 찍기:
git commit -m "feat: 한국관광공사 축제 데이터 수집 함수 추가"
💡 git status를 치면 빨간 글씨가 초록 글씨로 변했다가 깔끔하게 정리되는 모습을 볼 수 있습니다!
4

깃허브에 올리고 검토 요청하기 (Push & PR)

내 컴퓨터에서 저장한 내용을 깃허브 사이트로 쏩니다.

내 브랜치를 깃허브에 올리기:
git push -u origin 내브랜치이름
# 예시: git push -u origin feature/api-collector
🎉 깃허브 웹사이트로 이동하세요!
저장소 페이지 상단에 노란색 띠와 함께 [Compare & pull request] 버튼이 뜹니다!
그 버튼을 누르고 "무엇을 수정했는지" 간단히 적은 뒤 [Create pull request]를 클릭하면 끝!
5

팀원끼리 확인하고 원본에 합치기 (Merge)

이제 팀원이나 팀장(지호)이 깃허브 웹사이트에서 코드를 확인합니다.

  1. Files changed 탭에서 초록색(추가된 코드)과 빨간색(지워진 코드)을 확인합니다.
  2. "오 잘하셨네요! 문제없습니다" 싶으면 초록색 Merge pull request ➜ Confirm merge 클릭!
  3. 합쳐진 브랜치는 보라색 Delete branch를 눌러 깔끔하게 정리합니다.
✨ 놀라운 사실: main에 합쳐지자마자 Render와 Vercel이 알아서 자동으로 재배포를 진행합니다! (CI/CD)
6

다음 작업할 때 필수: 최신 코드 당겨오기 (Pull)

다른 팀원이 올린 코드가 main에 합쳐졌으므로, 내 컴퓨터의 main도 최신 상태로 업데이트해야 충돌이 안 납니다.

다시 main으로 돌아와서 최신 내용 받기:
git switch main
git pull origin main

이제 다시 2단계(새 브랜치 만들기)로 돌아가서 다음 작업을 시작하면 됩니다! 🔁

🚨

팀원 평화를 위한 3대 안전 수칙

1️⃣
절대로 main 브랜치에서 바로 코드를 수정하고 push하지 마세요!
반드시 git switch -c 새브랜치를 파서 작업하고 PR로 합치세요.
2️⃣
새 작업을 시작하기 전에는 무조건 git pull을 먼저 치세요!
옛날 코드를 바탕으로 작업하다가 나중에 코드가 엉키는(Conflict) 사고를 99% 막아줍니다.
3️⃣
.env 파일이나 비밀번호는 절대로 커밋하지 마세요!
우리가 이미 .gitignore 설정을 해두었지만, 키 값은 슬랙이나 카카오톡 시크릿으로만 공유하세요.
