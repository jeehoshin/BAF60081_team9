STEP 1 데이터 활용 기획 & 비즈니스 모델

데이터 7 : 모임 3
핵심 한 줄
공공 데이터에서 "공연은 서울·주말에 몰린다"는 격차를 발견했다 → 흩어진 3개 기관 데이터를 한곳에 모으고 → 동행 모임으로 "혼자라서 못 가는" 장벽을 낮춘다.

1 풀고 싶은 문제

🧩 정보가 흩어져 있다

공연은 KOPIS, 축제는 관광공사, 전시는 문화정보원. "이번 주말 우리 구에서 뭐 하지?"를 한 번에 볼 곳이 없다.

🙋 같이 갈 사람이 없다

기존 소모임 앱은 친목 중심이라 가입 장벽이 높다. "이 전시, 토요일 2시"처럼 활동 단위로 번개 동행을 구하기 어렵다.

📍 지역 격차가 있다

대전 같은 비수도권은 공연 공급 자체가 적다. 있는 축제·전시 정보라도 모으고, 사용자가 직접 올리는 활동(러닝)으로 채워야 한다.

3 비즈니스 모델

🎯 대상

서울 25개 구 · 대전 5개 구의 20~40대 성인. 가고는 싶은데 정보 찾기와 동행 구하기가 번거로운 사람.

🎁 제공 가치

① 공공 API 3종 통합 탐색 ② 4하(누가·언제·어디서·어떻게) 모임 카드 + 지도 ③ 오픈채팅 링크 없이 안전한 인앱 모임톡

✨ 차별점

목록 나열이 아니라 정제 + 출처 간 중복 탐지 + 인구 10만 명당 격차 분석을 같이 보여 준다. "공급 분석 + 동행 매칭"을 한 서비스에서.

💰 수익

  • 예매처 제휴 수수료 — 상세 화면 KOPIS 원본·예매 링크로 단체 관람 전환
  • 지자체·축제 프로모션(B2G) — 공급이 적은 자치구에 타깃 노출. 분석 데이터가 근거
  • 상권 쿠폰 — 집결지·뒤풀이 동선(how)과 로컬 카페 제휴

지속 운영: Vercel + Render + Supabase 무료 티어, 수집은 필요할 때만 실행 → 유휴 비용 0원. 만 19세 이상 확인, 참여자 30대(여) 투명 표기, 공공데이터 출처 문구 준수.

⚙️ 구현에서 신경 쓴 규칙 3가지

🔒 조건은 숨기지 않고 설명한다

성별·연령 조건 모임은 회색 카드 + 사유("이 모임은 30대만 참여할 수 있어요", "내 정보 입력하기")를 상세·지도·모임톡 어디서나 똑같이 보여 준다.

🛡️ 동시에 눌러도 정원은 지킨다

참여 요청마다 모임 행을 SELECT … FOR UPDATE로 잠가 정원(4~20) 초과를 막고, 호스트가 조건을 바꿀 때 기존 참여자와 충돌하면 거부한다.

👑 모임은 주인 없이 남지 않는다

호스트만 이름·일시·장소·정원·조건을 수정하고, 호스트는 나갈 수 없다. 일반 참여자만 나가기 가능.

STEP 6 시행착오 & 향후 계획

문제 → 해결
핵심 한 줄
공공 API는 기관마다 다 다르고, 빨리 부르면 막히고, 서버 시간은 UTC였다. 셋 다 테스트(71개)로 다시는 깨지지 않게 묶었다. 분석 숫자도 수집 방식이 만든 착시인지 따져 봤다.
문제① 공공 API 속도 제한 · 제각각인 형식KOPIS를 빠르게 연속 호출하면 Request Blocked. 세 기관의 날짜·좌표·분류 코드가 전부 다름.
해결초당 4건 제한 + 재시도, 정규화 파서시작일 00:00~종료일 23:59:59, 주소 → 'OO구', 분류 코드 매핑을 한 파서에 모으고 단위 테스트로 고정.
문제② 출처가 다르면 같은 행사가 두 번같은 공연이 KOPIS와 TourAPI에 동시에 있을 수 있어 중복 노출 우려.
해결같은 출처는 external_id, 다른 출처는 규칙 탐지단일 출처는 고유 인덱스 업서트. 출처 간은 제목(괄호·연도·기호 제거) + 기간 겹침 + 같은 구로 후보 검출. 실제 DB에서 겹침이 거의 없어 자동 삭제는 하지 않음.
문제③ Render 서버 시간이 UTC모임톡 시각과 "지난 시각 개설 방지" 검사가 9시간 어긋남.
해결now_kst()로 통일 + 1회 보정 마이그레이션모델·라우터 전부 KST 생성 함수로 바꾸고, 기존 UTC 행은 서버 시작 때 한 번 +9시간 보정.
문제④ 무료 서버는 잠든다Render 무료 플랜은 15분 쉬면 첫 응답이 30~60초.
해결세 겹 대비GitHub Actions가 낮 시간 10분마다 /health 호출, 발표 전 체크리스트, 늦으면 화면에 "서버 깨우는 중" 안내.
문제⑤ 인구로 나눴더니 대전이 더 많다?수집한 활동 수를 인구 10만 명당으로 나누자 서울 1.3 vs 대전 2.9. "인구 보정 후에도 서울 격차가 남는다"는 가설과 정반대.
해결원인은 수집 상한 → 도시 비교는 KOPIS 전수 통계로공연을 장르마다 도시별 6건까지만 받아 두 도시 수집량이 비슷하게 맞춰져 있었음(KOPIS 기준 실제 상연 횟수는 서울이 대전의 약 30배). 수집 활동 수는 도시 안 구별 분포에만 쓰고, 서울·대전 비교는 KOPIS 시·도 통계 ÷ 인구로 바꿈.
