4LLM · RAG · 에이전트 활용 계획

2:00 – 2:50

AI가 틀릴 수 있다는 전제로, 기능마다 "틀렸을 때 사용자가 무엇을 보고 무엇을 할 수 있는지"를 같이 정했습니다.

기능어떻게 (수업 주차)틀리거나 실패했을 때
🔎 한 문장 검색FastAPI /ai/parse가 LLM 구조화 출력으로 문장 → 조건 JSON. Pydantic으로 검증 (4주차)이해한 조건을 칩으로 보여 주고 바로 수정 · 확신이 낮으면 먼저 확인 질문 · 데이터에 없는 조건(예: "아이랑")은 "반영 못함"으로 표시 · 검증 실패나 429면 일반 필터 검색으로 전환
🧭 AI 동행 플래너행사 설명을 임베딩해 Supabase pgvector에 저장, 찾은 자료로만 답변 (5주차 RAG)근거가 없으면 답변을 보류 · 답변 속 행사명·날짜·가격이 출처 카드에 있는지 코드로 대조 · 문장마다 출처 번호
✍️ 모임 초안행사 정보 → 모임 이름·시간·소개 초안. 저장은 사람이 확인한 뒤 POST /meetups (4·7주차)AI가 쓴 칸에 "AI 초안" 배지 · 확인 창에서 손대지 않은 칸 수를 알려 줌 · 정원 4~20명 등 서버 규칙으로 다시 검사

모델: 수업 기본 Gemini Flash-Lite. 요청 한도에 걸리면 .env만 바꿔 Groq·로컬 모델로 전환 (4주차 OpenAI 호환 구조). 모임톡 대화 같은 개인 정보는 AI에 넣지 않습니다.

5주요 화면 UI 프로토타입

2:50 – 5:00 · 시연

클릭해 볼 수 있는 React 프로토타입입니다. 행사는 실제 공공 데이터이고, AI 응답만 시연용으로 흉내 냈습니다.

🔎 AI 검색

한 문장 입력 → 단계별 로딩 → "AI가 이렇게 이해했어요" 조건 칩 → 결과 카드. 칩의 ✕로 AI를 다시 부르지 않고 고칩니다.

🧭 AI 동행 플래너

답변 문장마다 [1][2] 출처 번호. 누르면 근거 카드가 강조됩니다. 근거가 없으면 "답변 보류".

✍️ 모임 초안

말투를 골라 초안을 다시 쓰고, 고친 칸은 "직접 수정"으로 바뀝니다. 마지막 확인은 사람이 합니다.

⏳ 로딩"문장 이해 → 행사 찾기 → 정리" 단계 표시, 4초가 넘으면 "그만 기다리고 직접 고르기"
🔍 결과 없음"무료 조건 빼기 9건"처럼 실제 건수가 붙은 완화 제안
🔌 오류 · 429원인을 쉬운 말로 안내, 다시 시도 또는 AI 없이 찾기
🤔 확신 낮음바로 찾지 않고 "이렇게 이해했는데 맞나요?"
  1. AI 검색 "이번 주말 서울 공연" → 조건 칩과 AI 응답 JSON → 칩 하나 빼서 결과가 바뀌는 것 보여 주기
  2. "아이랑 갈 만한 곳" → 확신 낮음 확인 + "‘아이랑’은 반영하지 못했어요"
  3. 왼쪽 아래 🎬 시연 상태를 "요청 한도 초과"로 → 오류 화면 → "AI 없이 조건 직접 고르기"
  4. 플래너 "이번 주말 종로구 공연 추천해줘" → [1] 눌러 출처 카드 → "주식 투자는 어떻게 시작해?"로 답변 보류
  5. 출처 카드의 "이 행사로 모임 만들기" → AI 초안 → 이름 고치기 → 확인 창

⚠️ 데이터가 금방 낡음

행사는 끝나면 사라집니다. 예약 수집을 붙이고, 화면에는 "끝난 행사 제외"를 표시합니다.

⚠️ 무료 서버·요청 한도

Render는 잠들면 깨는 데 1분쯤 걸리고, LLM은 429가 납니다. 저장본 표시, 모델 전환, AI 없는 검색으로 대비합니다.

⚠️ 개발 인력

React 전환이 가장 큽니다. 프로토타입 코드를 그대로 실제 프론트의 시작점으로 씁니다.
